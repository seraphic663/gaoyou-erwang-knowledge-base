# 结构切分规则 v2

本规则从原文件的排版线索推断阅读层级，不断言古籍的权威篇章或注者。原文、缺损、换行和 codepoint 坐标不改；已有 v1 数据库不更新。新建库默认 `--segmentation structure`，可用 `--segmentation fixed` 选择原先的 600 字、重叠 100 字窗口。

## 原文中可核对的形态

- `data/A-原著原典/读书杂志_王念孙.md:147,151,153-159` 用 `##` 排书和卷，`###` 排条，条内有正文和 `<small>` 小注。《经义述闻》同类条头见 `data/A-原著原典/经义述闻_王引之.md:19-25`。
- `data/A-原著原典/经传释词_王引之.md:55-73` 的 `### 與` 下有多段文字，应属于同一词条。《广雅疏证》在 `data/A-原著原典/广雅疏证_王念孙.md:51-57` 用 `##` 标卷、`###` 标释诂，其下词串和疏证没有一致的 Markdown 条头；此处仅保留已明示的层级。
- 外典的显式标识也不同：`data/daizhigev20/高频/艺文类聚.md:23-26` 的 `●卷／○类／◇条`，`data/daizhigev20/中频/白虎通义.md:26-29` 的 `●卷／○类`。
- 字书/韵书可见 `data/daizhigev20/低频/说文解字注.md:21-25` 的“部→字头→注解”，以及 `data/daizhigev20/中频/唐韵正.md:30-39` 的独立短字头或字头带音切，下一行接成对方括注。`data/daizhigev20/高频/集韵.md:29-40` 有卷、声部及一整行密集字释，不能假定每行都能细分成条。
- 目录与正文会重复标题：`data/daizhigev20/低频/诗经.md:20,332-337` 都出现“国风 周南 关雎”；`data/daizhigev20/高频/荀子.md:42,97-100` 也重复“劝学篇第一”。因此短行只作为候选，目录文字原样保留，孤立标题的 `toc_candidate` 供审阅。

## 实施规则

1. 独立行的 Markdown 标题、`●／○／◇`、明确卷/部和篇第格式建立暂定层级。短字头紧接“注解：”或成对注释行时标为条头；其他独立短标题只标 `candidate`。不按书名或特定字制定规则。成对 `【】`、`（）`、`[]`、`()` 和 `<small>…</small>` 的内部不产生标题或段落边界。
2. 标题及其后内容一直归同一父范围，直到下一标题。无标题正文按空行成段；明显单独成段的注释并入紧邻的上一正文段，其余独立短段仍保留。
3. 完整父范围不超过 1200 codepoint 时保持完整。长范围以约 600 为目标，优先找段落、句末、行末；没有足够自然边界时才使用 600/100 的固定窗口兜底。可识别的成对注释范围尽量不切开；过长注释不得不切时记录前后续接。
4. `chunks.structure_json` 保存 `parent_id`、父范围、带原文区间的 `heading_path`、分片序号/总数、续接和注释跨片标记。此字段与旧 `flags_json` 分开；旧库没有该字段。片段和标题区间都是原文件 Unicode codepoint 的左闭右开位置。`role` 是排版角色，不是正文/注释作者判定。

测试只使用合成文字；尚未做全库重建或独立人工分层审阅。短行、目录和无明确标题的词串仍可能需要人工检查。
