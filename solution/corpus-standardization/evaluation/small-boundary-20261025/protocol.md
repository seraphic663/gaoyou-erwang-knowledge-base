# 古籍片段边界消融：冻结前协议

## 范围与输入

本实验只读取同目录的 `public_inputs.json`，格式为 `{"items":[{"id":"...","text":"...","target_quote":"..."}]}`。运行器只接收这三个字段；每例必须有唯一 `id`、非空 `text` 和非空 `target_quote`。`target_quote` 必须出现在删除标签后的文本中。预定 21 例，其中原定 18 例保持不变，另加 3 例独立裸短音注困难层并单独报告；实际数量和输入 SHA-256 在运行时记入元数据。不得读取样本答案、隐藏评分或业务库，不修改原文。

两条件是 `tagged`（原始 `text`）和 `untagged`（只将字面量 `<small>` 与 `</small>` 替换为空串）。不解析 HTML，不清理其他标签，不重排、不归一化、不修剪文本中的任意字符、空格或换行。对同一例，两条件的 `id`、`target_quote`、系统提示词、用户提示词模板及 API 参数相同，唯一差异是插入模板的片段文字。运行器逐例断言 `untagged == tagged.replace('<small>', '').replace('</small>', '')`。

## 固定提示词

系统消息全文：

> 你是古籍片段的文本边界判读员。只依据本次给出的片段和目标字句判断，不调用外部资料，不补造原文。这里的“原书正文”专指当前考辨所引用或解释的底本文句，不是片段中所有非注释文字；考辨者自己的论证不能直接算作底本文句。目标附近的文字可能属于原书正文、读音、校记、出处、案语，也可能无法判断。排版标记只是线索，不预设所有小字属于同一种角色。逐项提取与目标判读有关的连续字句，不必穷尽无关内容。每项 exact_quote 必须从片段中逐字复制一段连续文字；role 只能是“正文”“读音”“校记”“出处”“案语”“无法判断”之一；explains_quote 填这项文字明确解释、校订或标音的对象原句，若无法确定则填 null；reason 简要说明可见的判读依据。另在 book_quotes 中列出与目标有关、能可靠作为原书正文引用的底本片段；可用多个连续原文片段表示被插注隔开的底本文句，不必拼成一整句，也不得补字。只有考辨叙述或无法确定底本文句时，用空数组，不要凑引文。不得把读音、校记、出处、案语写入 book_quotes。只返回 JSON 对象，格式为 {"items":[{"exact_quote":"...","role":"...","explains_quote":null,"reason":"..."}],"book_quotes":["..."]}。不要输出 Markdown 或额外说明。

用户消息模板全文（`{target_quote_json}` 和 `{text_json}` 分别替换为 JSON 字符串字面量；两条件共用模板）：

```text
请判读下列片段中与目标字句有关的文字边界及归属。
目标字句：{target_quote_json}
片段：{text_json}
```

提示词列出任务的通用角色，不包含任何个例的预期类别、正确答案或标签含义说明。`<small>` 保留条件仅向模型显示原始片段；不增加标签解释。每次请求只有以上两条消息，不带历史、检索内容、示例或评分材料。

## 请求与顺序

沿用网站已有 DeepSeek 接口 `https://api.deepseek.com/chat/completions`、`deepseek-flash`、`reasoning_effort=high`、`max_tokens=32768` 和 `response_format={"type":"json_object"}`；网站此配置也不显式设置 `temperature`。高预算覆盖推理 token 和 JSON 输出，实际消耗以响应的 usage 为准。凭据只从本进程环境变量或 `solution/website/.env` 的 `DEEPSEEK_ANALYSIS_API_KEY`、`DEEPSEEK_API_KEY_BACKUP`、`DEEPSEEK_API_KEY` 中按网站优先级读取；绝不写入请求日志。

每例每条件独立调用两次，共预定 `21 × 2 × 2 = 84` 次。固定随机种子 `20261025`：每轮打乱例序，每例的两条件以随机但固定的先后顺序成对排入计划，双轮独立。并发为 2。实际完成次序可能不同，日志同时记计划序号、开始与结束时间。网络连接或超时类传输失败最多重试两次；HTTP 非成功响应、响应 JSON/模型输出不合法、内容错误、截断均不重试，也不修改提示词。连续两次出现认证/权限、余额或模型不可用类 HTTP 错误时停止向 API 发送余下计划，报告已发与未发数量及阻断类型；首个此类错误后暂停补充并发，仅等待另一在途请求，以免空跑整批。连接配置可按服务器实际错误排障，不凭模型内容修改提示词。每次尝试单独记日志。

## 记录与评分边界

运行时在独立结果目录记录输入与提示词 SHA-256、参数、固定计划、每次尝试的完整请求体（不含密钥或 Authorization）、HTTP 状态、完整响应、返回模型、usage、开始/结束时间、传输/解析/格式错误。输出格式检查仅判断 JSON 结构、角色枚举、字段类型及原样引文是否出现在输入片段中；不得以答案好坏触发重试。

运行器不读取、合并或评分隐藏标注。后续盲评分由母任务统一执行：评分对象是目标与其中心小注的关系，角色识别、归属对象、原书引文混入注文各按 0/1/2（错误/部分或保留不确定/正确）记分；另列“误引注文为正文”的严重错误和“证据不足时合理弃答”。JSON 不合法、字段错误、截断等列为运行异常，不强行判作内容正确或错误。可解析输出即使逐字引文不是输入的连续子串，也须保留原样供人工评审；将此格式偏差与角色、归属的语义错误分开记录。所有评分须保留 tagged/untagged 配对和两次重复，报告改进、退步、平局及不确定，不能把此小样本视为全库准确率。

准备阶段只写协议与运行器；执行必须显式传入冻结提示词 SHA-256 与 `--execute`。
