# 通用古籍切分规则 v3

此规则只按可见排版建立暂定阅读结构，不断言原书权威目录、作者或注者。原文、UTF-8 字节、BOM、换行及 Unicode codepoint 坐标不改；旧库不覆盖。`segmentation_v2.py` 是改动前的同哈希基线。新构建显式用 `--segmentation structure-v3`；`structure` 是它的别名，`fixed` 仍可选。

## 规则与边界

1. 只有“目录/目錄/目録”标识加至少数项短标题，或至少八项短标题且至少三项在该目录区之后作为正文标题重现，才将该区标为 `toc`。标题间至多容许两个空行，遇到后接正文的标题就结束目录。单靠短行不判目录；其余标题仍以 `confidence=candidate`、`toc_candidate` 暴露不确定性。目录标题不进入后续正文的 `heading_path`，目录结束清空层级。
2. Markdown、●/○/◇/◎/※/△、卷/巻（含“卷之二”）、篇/章/列传第 N 等标题按统一层级处理；新卷替换旧卷及其条，收束语（如“右章第一”）单独标 `closure` 并终止旧归属。无法可靠定级的独立短题清除旧层级，只以候选标题记录。页眉、残缺和异体格式仍可能无法自动判定。
3. 独立序、跋、后记等标 `paratext`，脚注/校记块标 `notes`；这些只是排版角色，不把“序跋”“史臣曰”“赞曰”一概判作现代编辑文字。新正文卷篇从上述块退出时清除其父级。
4. 每个父范围约以 600 codepoint 分片，单片及阅读窗口均不超过 1200。先找段、句、行界；在有引文线索且下一段是短署名案语或解释标记时，识别引文到相邻解说行的范围，范围能装入 1200 时优先在其前后切，连同解说第二句等内部切点一起避开。内联成对注释也尽量不切。若上限内无法保全，记录跨片关联与续接，仍保留全部原文；无合适自然界时按约 600 codepoint 顺序硬切，片段不重叠。这与 v2 的无自然界 600/100 重叠兜底不同；独立 `fixed` 模式仍用 600/100 重叠，比较结果应把兜底重叠变化视为变量。

`chunks.role` 可为原有 `paragraph`、`chapter`、`entry`，或新增的 `toc`、`closure`、`paratext`、`notes`。`structure_json` 保留原有父范围、标题路径、分片序号、`toc_candidate`、注释续接等字段，新增 `association_links`（原文 codepoint `at_cp`、`range_start_cp`、`range_end_cp`、`within_limit` 与 `basis`，后者取值 `quote_explanation` 或 `attached_note`）、`association_continued_from_previous`、`association_continues_next`。这些线索只反映排版相邻关系，不代表引文归属、释义正确或检索质量。

新测试仅用合成反例检查目录、短诗、跨格式卷篇、收束语、序跋、引文解说、超长解释、映射及正文覆盖。全库构建还须核验原文哈希、无遗漏覆盖、坐标、窗口、映射、外键与 SQLite 完整性；机械通过不等于学术判断通过。
