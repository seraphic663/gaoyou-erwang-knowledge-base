# 项目文献目录

`04-项目文献` 保存项目研究材料。这里不是网站运行目录，主要作用是支撑申报书、数据库字段设计、案例选择和答辩说明。

## 目录结构

```text
04-项目文献/
├─ 0-当前阅读/    当前正在使用的摘录、案例分析和术语材料
├─ A-原著原典/    王念孙、王引之及相关原典文本
├─ B-一级资料/    高邮二王合集、遗书等一级资料
├─ C-二级资料/    论文、专著、研究综述等二级研究材料
└─ D-标注/        小组标注稿、成员整理成果
```

## 使用优先级

1. 先看 `0-当前阅读/`，这里最接近当前网站和数据库展示口径。
2. 查原文出处时看 `A-原著原典/` 和 `B-一级资料/`。
3. 需要理论支撑和研究史说明时看 `C-二级资料/`。
4. 需要追溯小组工作成果时看 `D-标注/`。

## 仓库维护建议

- 当前阅读笔记和标注稿应保留在 Git 内，因为它们直接支撑网站叙事和数据库建设。
- 大体量 PDF、CAJ、DOCX 文献有研究价值，但不一定适合长期放在 Git 主仓；后续可迁出到网盘、归档盘或 Git LFS。
- 如果迁出大文件，应在本 README 中保留清单、外部位置和用途说明。
- 不要把临时下载文件、重复扫描件、Office 锁文件提交进仓库。

## 与网站和数据库的关系

- 网站代表性案例、术语页和数据库说明应优先引用 `0-当前阅读/` 中已经整理过的材料。
- `02-数据库/source.txt` 是结构化入库的直接输入，不应由本目录中的大文件直接替代。
- 文献目录负责保存研究依据；数据库目录负责把可结构化的内容转成可检索数据。
