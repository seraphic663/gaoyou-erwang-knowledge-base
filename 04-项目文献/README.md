# 项目文献目录

`04-项目文献` 是“高邮二王考据过程知识库”的研究材料区，保存原典、一级资料、二级研究、当前阅读笔记和人工标注成果。这里不是网站运行目录；网站只读取 `03-项目网站/data/` 中的 JSON 快照，数据库重建则由 `02-数据库/` 负责。

## 内部架构

```text
04-项目文献/
├─ 0-当前阅读/    已经进入项目论证和网站叙事的工作笔记
├─ A-原著原典/    王念孙、王引之核心著作的整理文本
├─ B-一级资料/    高邮二王著作合集、遗书等综合性原始资料
├─ C-二级资料/    研究论文、学位论文、理论参考和数字人文参照
├─ D-标注/        小组标注稿、DOCX 转 JSON、AI 整理结果和标注库输入
└─ scripts/       文献格式转换和一致性维护脚本
```

各目录分工如下：

- `0-当前阅读/` 是当前研究口径的最直接来源，适合写申报、答辩、网站说明和数据库字段解释。
- `A-原著原典/` 是查二王原文、选案例、核对训释的核心底本。
- `B-一级资料/` 是合集型资料，适合补查版本、序跋、附录、遗文、正误和未单独拆出的材料。
- `C-二级资料/` 用于研究史、方法论、理论边界和数字人文参照。
- `D-标注/` 是把文献案例转成结构化数据的工作区，标注结果最终进入 `02-数据库/data/annotations.db`，不混入主库 `dictionary.db`。

## 使用顺序

1. 要快速理解当前项目怎么讲，先看 `0-当前阅读/`。
2. 要核对王念孙、王引之原文，查 `A-原著原典/`。
3. 要找合集、版本、序跋或补充材料，查 `B-一级资料/`。
4. 要写理论依据、研究综述或方法论说明，查 `C-二级资料/`。
5. 要追溯人工标注和 AI 释证数据来源，查 `D-标注/`。

### scripts

| 文件 | 内容大意 | 项目用途 |
| --- | --- | --- |
| `scripts/convert_docx_to_md.py` | 统一把 `A-原著原典/`、`B-一级资料/` 和归档的 `0-当前阅读/` DOCX 转成 Markdown。A 按 Word 标题样式和字号识别层级；B 保持页码型 OCR 文本；当前阅读模式逐段保留正文、脚注、Word 批注和锚定文字。 | 保证三类 Markdown 可复跑、规则一致，并可通过脚本复核正文或批注是否漏字。 |

转换经验：

- A 类原典适合转成“可检索、可阅读、可入库”的 Markdown，不适合声称完全复刻 Word 版式。
- `读书杂志_王念孙.docx` 中的 `Table of Contents`、中文总目录、条目内部跳转和书签主要服务 Word 内部导航，Markdown 中不保留这些跳转结构，只保留正文标题和正文文字。
- `media` 是 DOCX 包里的图片文件，`drawing` 是图片或图形对象在正文中的位置；这些内容不嵌入 Markdown。需要判断封面、异体字图、缺字图或版式时，回到归档 DOCX/PDF。
- 小字是有阅读意义的夹注、注释或校勘说明，转换时保留为 `<small>...</small>`，不丢弃。
- B 类合集是 OCR 型页码文本，保持页码标题比强行识别章节更稳妥；`### 第xx页` 是唯一结构化改动。
- 转换后曾做一致性审查：A 四份 Markdown 主体文字与脚本抽取的 DOCX 正文一致；B 六份 Markdown 将 `### 第xx页` 还原为 `【第xx页】` 后，正文字符与 DOCX 抽取结果一致。
- 当前阅读的 Markdown 可直接从归档 DOCX 重建：`python 04-项目文献/scripts/convert_docx_to_md.py --root 04-项目文献 --section current`。该模式以正文边界标记执行逐段一致性校验，并检查每条 Word 批注正文及锚定文字是否写入输出。

## 与数据库和网站的关系

```text
04-项目文献/D-标注/*.docx
  -> 04-项目文献/D-标注/json/run.py
  -> 04-项目文献/D-标注/json/full_json/
  -> 04-项目文献/D-标注/json/ai_json/
  -> 02-数据库/data/annotations.db
  -> 03-项目网站/data/annotation-snapshot.json
  -> 03-项目网站/web/annotation.html
  -> 03-项目网站/web/ai-annotation.html
```

主库 `dictionary.db` 的直接输入仍是 `02-数据库/main/source.txt`。本目录的大文件不直接替代主库输入；它们负责保存研究依据、阅读材料和标注来源。

## 维护原则

- 当前阅读笔记、人工标注稿和 JSON 流程说明应保留在 Git 内，因为它们直接支撑网站叙事和数据库建设。
- 大体量 PDF、CAJ、DOCX 文献有研究价值，但不一定适合长期放在 Git 主仓；如迁出，应在本 README 保留清单、外部位置和用途说明。
- `D-标注/json/.env`、`__pycache__/`、临时下载文件、Office 锁文件不应提交。
- PDF/CAJ 的“大意”如果来自题名或抽取不稳定的首页文字，应在后续正式引用前回到原文核验。
- A、B 两类 Markdown 的正文不建议手工改；如需重建，应先从 `05-归档文献/` 取回相应 DOCX，再分别运行 `--section A` 或 `--section B`。当前阅读 Markdown 可直接用归档底本运行 `--section current` 重建。如发现 OCR 或原文问题，应先回到归档 DOCX/PDF 底本确认。
