# external source research

研究日期：2026-08-12

研究范围：只读检查 `v2/data/real_runs/annotation_v2.db` 的 `external_source_registry`、`annotation_evidence_external_sources` 和 evidence JSON；外部检索优先覆盖高频来源和能够承载 80 条 `external_source_pending` 证据的作品族。本文件是外部来源调查记录，不是 canonical 注册结果；本轮没有修改 V2 数据库、schema、代码或既有原典 Markdown。

## 1. 当前 V2 待补来源的事实基线

数据库中有 100 个 `external_source_registry`，状态全部是 `pending`；这些 registry 被 121 条 evidence link 使用。121 条外部证据中，80 条的 `source_resolution=external_source_pending`，41 条只是王氏四种正文中的 `secondary_citation_match`。因此，后者只能证明引文出现在王氏正文上下文中，不能证明引文已经回到被引外部原典。

按 registry 绑定次数，当前最高频来源是：说文解字 13 条、玉篇 4 条、书·洛诰 2 条、吴语 2 条、尔雅 2 条、礼记·曲礼 2 条、礼记·檀弓 2 条、礼记·祭统 2 条；其余大多是单篇或单条引用。按仍待外部定位的 80 条证据，最高频是说文解字 4 条、礼记·檀弓 2 条，其余包括诗经、书、礼记、左传、管子、庄子、史记、汉书、方言、经典释文、仪礼、谷梁传等单条来源。

现有数据库的外部证据仍保持 `quote_check=unchecked`，本文件中的网页命中、全文搜索或 OCR 命中都不改变这一状态。

## 2. 评价规则

本轮把“可公开访问”“有版本信息”“可精确回到段落”分开判断：

- 可公开访问：能够稳定打开全文页或馆藏条目；不能仅凭搜索结果摘要认定。
- 有版本信息：页面明确给出底本、丛刊/四库/十三经注疏等版本、作者或馆藏来源。
- 可精确核验：至少有篇名/卷次/段落或章节锚点，并能把机器文本与影印图像互校。
- 可下载完整文本：优先指公开的整部扫描或稳定的机器文本入口；“网页可搜索”不等于已取得可冻结的完整本地文件。
- canonical 候选：即使满足以上条件，也只能先作为 `external_canonical_candidate`；只有下载、记录文件及版本信息、生成 passage、做 quote-in-passage 和人工底本确认后，才能写入 V2 的 canonical registry。

优先来源层级是：馆藏影印/可下载扫描 > 带底本说明的 CText OCR/全文 > 维基文库等可导出文本。OCR 只能用于定位，不能跳过影印页核对。

## 3. 已检索到的高可信公开来源

### 3.1 中国哲学书电子化计划（CText）总入口

- URL：[CText 中文首页](https://ctext.org/zhs)，[引用指南](https://ctext.org/faq/cite/zhs)。
- 版本/edition：CText 明确将其定位为开放电子图书馆，并在各作品页列出电子底本和相关版本；引用指南要求引用时保留作品页链接。
- 完整文本：多数先秦两汉经典和子书有可浏览的机器文本；部分“图书馆”条目显示 IA 扫描分册下载入口。
- 精确核验：可以按稳定的作品/篇名 URL 和段落编号定位，适合生成候选 passage；若要作为 canonical，仍需保存对应影印文件或图像页并以图校 OCR。
- 风险：CText 同时收录多个版本，默认文本的版本选择必须写入 source document；网站页面会显示 OCR 初稿、用户修订或不同底本，不能只保存一个作品名。
- 建议：先用 CText 进行高频引用的篇章定位，再从其 Library 条目取得对应馆藏扫描，形成“扫描页 + OCR passage + 版本说明”的本地冻结包。CText 的页面不能直接替代本地 hash 和版本登记。

### 3.2 《说文解字》

- 公开全文：[CText《说文解字》底本页](https://ctext.org/shuo-wen-jie-zi/zhs)，[CText《钦定四库全书》本《说文解字》](https://ctext.org/library.pl?if=en&res=77356)，[维基文库《说文解字》](https://zh.wikisource.org/zh-hans/%E8%AA%AA%E6%96%87)。
- 版本/edition：CText Library 条目明确列出《钦定四库全书》本，15 卷，分 8 册，来源为浙江大学图书馆，扫描者为 CADAL，并列出 IA 下载入口。维基文库页面有 15 卷结构和 EPUB/MOBI/PDF 导出入口，但其协作编辑文本不能单独作为底本证明。
- 完整文本：机器全文可访问；《钦定四库全书》本的整部影印分册有公开 IA 入口。维基文库也能导出整部机器文本。
- 精确核验：适合。条目可按卷次、部首、字头定位；最终必须对照影印页，尤其处理篆体、异体、重文、缺字和 OCR 错字。
- 版权/版本风险：古籍正文属于公版范围，但数字扫描、OCR 和协作整理的版权/许可要分别记录；“说文解字”“段玉裁注”“说文解字系传”不是同一 source。不要用《说文解字注》替代旧 AI 里明确写作《说文解字》的引文。
- 建议：这是第一优先来源。先取得 CText Library 的《钦定四库全书》本扫描或另一明确底本，固定一个 edition；对 13 条 registry evidence 生成 13 个候选定位，再以影印页逐条确认。

### 3.3 《玉篇》

- 公开全文/版本：[CText《古逸丛书》本《玉篇》](https://ctext.org/library.pl?if=en&remap=gb&res=80891)，[CText《玉篇》卷一](https://ctext.org/wiki.pl?chapter=470060&if=en)。
- 版本/edition：CText 的《古逸丛书》条目说明其为《古逸丛书》本，并列出“古逸丛书之十一玉篇 1/2”；CText Wiki 卷一页面显示其文字来自《钦定四库全书》系统并注明 OCR。该页面还明确说明后世《玉篇》存在顾野王本、唐孙强增字本、宋陈彭年等重修本和明内府本的差异。
- 完整文本：不能直接认定“顾野王原本完整可下载”。公开可见的是辑存残卷、后世重修本或四库系统文本；《古逸丛书》条目只有两册，不能当作原本三十卷完整本。
- 精确核验：可对后世特定版本做章节/卷次和字头核验；对旧 AI 没有 edition 的“玉篇”引文，只能先做 `edition_unresolved`，不能自动变成 canonical。
- 版权/版本风险：这是本轮最高版本风险来源。将“玉篇”泛化为一个唯一文本会混淆顾野王原书、孙强增订、宋重修和后世辑本；OCR 还可能混淆异体字和残缺字。
- 建议：先人工决定要核验的 edition。若目标是“现存公开可校文本”，可选择《古逸丛书》残卷或四库重修本并明确写入 edition；若目标是顾野王原本，当前公开资源不足以支持“完整原本”结论，应保持 pending。

- 精确核验：较适合。旧证据若只有“尔雅”而没有注疏层次，须区分经文、郭璞注、邢昺疏，记录到 paragraph/section。

- 建议：第二优先。对 3 条相关证据分别判定是《尔雅》经文还是《尔雅注疏》，固定一个 edition 后再生成 passage。

### 3.5 《礼记》

- 公开全文/版本：[CText《礼记》](https://ctext.org/liji/zh)，[《仿宋相台五经》本《礼记》](https://ctext.org/library.pl?if=en&res=77828)，[《钦定四库全书》本《礼记大全》](https://ctext.org/library.pl?if=en&res=5230)。
- 版本/edition：CText《礼记》页列出《武英殿十三经注疏》本《礼记正义》《仿宋相台五经》本、《阮元校刻十三经注疏》本、《四部丛刊》本以及多种四库注本；仿宋相台页面按册列出曲礼、檀弓、礼运、郊特牲、乐记、表记、大学、射义、聘义等篇。
- 完整文本：经文全文可在线访问；《仿宋相台五经》条目覆盖 20 卷，具备较好的篇章分册路线；《礼记大全》条目还明确列出浙江大学图书馆/CADAL 和 IA 分册。
- 精确核验：适合。80 条 pending 中涉及檀弓、曲礼、祭统、礼运、月令、大学、乐记、表记、郊特牲、聘义等，均可按篇名建立目标 passage；但必须选择经文、注疏或集说中的一个层级。
- 版权/版本风险：同一篇在经文、郑玄注、孔颖达疏、明代集说和清代四库注本中不是同一文本；“礼记”不能覆盖“礼记郑玄注”或“礼记卢植注”。
- 建议：按出现频次先处理檀弓、曲礼、祭统，再扩展其他篇目；对于注明郑玄注/卢植注的证据，必须另建 commentary edition，不得使用经文命中代替注文命中。

- 建议：先固定《武英殿十三经注疏》本《尚书正义》作为经文/正义主线，另外把《书经集传》作为独立 commentary/source document，不得混合 quote。

- 建议：先按旧 evidence 的具体引文决定是正文还是注文，再为每个注家建立独立 source document；正文命中不能让 `管子注` 自动通过。

### 3.11 国家图书馆/中华古籍资源库与维基文库的定位

- 国家图书馆官方说明：[中国古籍保护网关于数字古籍资源](https://www.nlc.cn/pcab/zx/xw/20240131_2637771.shtml)。该页面说明“中华古籍资源库”是国家图书馆及国家古籍保护中心建设的数字资源平台，并给出数字古籍入口；它适合确认馆藏和版本来源，但本轮没有通过公开页面验证对每个目标作品都存在无登录、可批量下载的稳定文件接口。
- 国家图书馆馆藏扫描的一个公开镜像样例：[国家图书馆藏《说文解字注》扫描元数据](https://commons.wikimedia.org/wiki/File%3ANLC892-312002096002-312732_%E8%AA%AA%E6%96%87%E8%A7%A3%E5%AD%97%E6%B3%A8_%E5%8D%81%E4%BA%94%E5%8D%B7_%E7%AC%AC1%E5%86%8A.pdf)。页面明确记录作者、石印本、1910 年出版信息、国家图书馆馆藏和 PDF 页数，说明“馆藏扫描”能够成为版本证据，但镜像的许可与使用范围仍需逐项核对。
- 维基文库的《说文解字》页面提供整部卷次和 EPUB/MOBI/PDF 导出；它适合快速生成候选和交叉检索，不适合在没有底本信息和图像复核时直接登记 canonical。其页面也明确声明协作文本的许可和附加条款，故下载后应记录来源页面和版本日期。

## 4. 当前结论：哪些可以推进，哪些不能直接通过

### 可以推进到“外部 canonical candidate”

1. 《说文解字》：优先采用 CText《钦定四库全书》本及其 IA 分册，或另选有明确版本的国家图书馆扫描；13 条 registry evidence 可以进入下载和 passage 生成队列。
2. 《礼记》：优先处理檀弓、曲礼、祭统，再扩展礼运、月令、大学、乐记、表记等；须为经文、郑玄注、卢植注分别建版本。
3. 《左传》：按年份下载 CText Library《春秋左传正义》覆盖当前引用的分册，具备最清楚的卷年定位。
4. 《尔雅》：可固定《武英殿十三经注疏》本《尔雅注疏》或《四部丛刊初编》本《尔雅》，并保留经文/郭璞注/邢昺疏层次。
5. 《尚书》《诗经》《庄子》《管子》：已经有篇章全文和版本化 Library 路线，可进入下一轮批量下载和冻结。

### 不能直接当作 canonical

- 任何 CText 搜索结果摘要、相似段落结果、AI 翻译或没有 edition 的默认网页文本。
- “玉篇”不注明顾野王本、孙强本、宋重修本、四库本或《古逸丛书》本时。
- “管子注”“郑玄注”“卢植注”“颜师古注”“虞翻注”等只写注家但没有具体底本时。
- 只在王氏四种 Markdown 中出现的二次引文。它们仍是 `secondary_citation_match`，不是外部原典 quote passed。
- 维基文库协作文本、普通 OCR 文本或机器下载文件，若没有相应影印图像和版本记录。

## 5. 下一步建议（仍可自动完成的部分）

1. 在不改数据库的前提下，先下载并保存《说文解字》《尔雅》《礼记》檀弓/曲礼、《左传》相关年份、《尚书》相关篇、《诗经》相关篇、《庄子》相关篇、《管子》形势/地员/形势解的公开扫描或机器文本；每个文件记录 URL、edition、馆藏来源、下载时间和 hash。
2. 写一个只读/产物型 external-source fetch manifest，不直接写 `external_source_registry`；先检查下载文件是否完整、是否含扫描图像、是否有卷次/篇章索引。
3. 用 CText 页面做候选定位，用下载的影印图像做最终 quote 核验；生成 `external_passage_candidates` 和 `quote_match_report`，仍保持数据库现有 evidence 为 `unchecked`，直到版本和图文复核完成。
4. 先处理 13 条《说文解字》、4 条《玉篇》、礼记和左传高频条目，再扩展 100 个 registry 的其余单条来源。不要一开始把 100 个 registry 合并成“经典全集”而丢失篇名、注家和版本差异。
5. 对没有公开完整底本、只有搜索结果或不清楚注家的来源，生成明确的 `blocked_external_source` 队列，原因写成“版本不足”“仅有二次引文”“无法取得完整扫描”或“需人工选择注本”，不要降低 quote 标准。

本轮外部检索的最终判断是：高频来源中，除《玉篇》原本完整性和若干具体注本外，大部分已经找到可公开访问、带版本信息、可继续下载/冻结的候选来源；但尚未完成本地下载、文件完整性确认、版本冻结和逐条图文核验，因此没有任何一条 external evidence 被宣称为 canonical passed。

## 6. 本轮实际获取与自动匹配结果（2026-08-12）

本轮先直接测试 CText 的机器接口和篇章页面。CText API 对 `gettext` 返回认证要求，连续访问篇章页面后也出现人机验证/403；因此没有把 CText 网页或 API 响应伪装成本地 canonical 文件，也没有绕过验证。CText 仍保留在来源调查报告中，作为版本和篇章入口，不作为本轮已下载的证据。

随后使用维基文库公开 MediaWiki API 对当前 80 条 `external_source_pending` 引文逐条搜索，并在页面标题命中被引作品/篇名时保存 revision 原文。结果已经写入 `v2/data/real_runs/external_public_candidate_manifest.json`、`v2/data/real_runs/external_passage_candidates.passage.v1.jsonl` 和 `v2/data/external_sources/wikisource_candidate/pages/`；manifest 的最终 hash 记录在同名 `.sha256` 文件中。

实际结果为：80 条中 1 条达到“公开页面原文可匹配”的候选状态，11 条只有被引作品相关页面的搜索命中但 quote 未成为当前原始 wikitext 的连续子串，68 条没有找到满足标题过滤的公开页面候选；共保存 22 个页面原文文件。唯一的 `candidate_found` 是 `legacy-ai:16` evidence 8 的“礼记·礼运”引文“山川所以儐鬼神也。”，其页面候选包括 `禮記/禮運`，另有 `禮記注疏` 和 `日講禮記解義` 的相关页；这仍然只是公开转录候选，未选择 edition、未做影印图文核验。

数据库只把对应外部 registry 从 `pending` 更新为 `registered`，并写入候选 manifest 路径、hash 和“edition unresolved”说明；80 条 external evidence 的 `quote_check` 仍为 `unchecked`，没有新增 canonical external passage，也没有改变人工状态或 gold 状态。剩余 99 个 external registry 仍是 `pending`，说明自动抓取已经把“未找到”“只有搜索线索”“找到公开候选但未核验”分开，而不是用搜索结果冒充证据。
