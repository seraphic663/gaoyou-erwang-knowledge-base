# 网站部署迁移说明

更新日期：2026-05-14

## 当前结论

项目当前采用 Railway 部署，根目录 `railway.toml` 指定 `DOCKERFILE` 构建。容器启动后执行：

```bash
npm start
```

实际启动链路：

```text
package.json
  -> node 03-项目网站/server.js
  -> 03-项目网站/src/http-server.js
  -> 读取 03-项目网站/data/sqlite-snapshot.json
```

线上运行不需要直接执行 `02-数据库` 内的 Python 脚本，也不需要现场解析 SQLite。Python 脚本用于本地重建数据库和导出快照。

## 平台要求

必须具备：

- Node.js 18+
- 可暴露 HTTP 端口
- 支持 `PORT` 环境变量
- 能提供静态页面和 `/api/*` 接口

当前不必须具备：

- 独立数据库实例
- Redis
- 对象存储
- 消息队列
- 在线写入持久化

## 不能当纯静态站部署

本项目依赖后端接口：

```text
/api/health
/api/bootstrap
/api/search
/api/schema
/api/terms
/api/cases
/api/term
/api/case
```

因此不能只把 HTML/CSS/JS 上传到纯静态托管平台，必须选择能运行 Node 服务的平台。

## 国产平台迁移建议

优先级：

1. 腾讯云 CloudBase Run：最接近 Railway 的轻量 Web 服务部署体验。
2. Sealos：适合演示、图形化管理和后续容器化扩展。
3. 阿里云 SAE：适合后续更正式的长期运营，但配置心智更重。

迁移时原则上不需要改业务代码。当前仓库已经在根目录保留 `Dockerfile` 和 `.dockerignore`，国产平台优先复用这套容器构建配置。

## 最小 Dockerfile 示例

```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package.json ./
COPY 03-项目网站 ./03-项目网站
ENV NODE_ENV=production
ENV PORT=3000
ENV DATA_SOURCE=sqlite
EXPOSE 3000
CMD ["npm", "start"]
```

线上容器只需要网站快照，不需要复制 `02-数据库/data/dictionary.db`。根目录没有 `server.js`，不要在 Dockerfile 中写 `COPY server.js ./`。

## 迁移检查

部署后检查：

```text
/api/health
/api/bootstrap
/api/search?q=始
/database.html
/term.html
/case.html
```

如果 `/api/health` 返回 `source: sqlite` 或能说明已读取 `sqlite-snapshot.json`，则数据链路正常。

## 当前建议

近期如果目标是答辩展示，Railway 能稳定访问时不建议临时切换主平台。更务实的做法是保留 Railway，同时并行试一套国产平台环境；确认稳定后再切换展示地址。
