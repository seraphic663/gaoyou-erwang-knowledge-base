# 架构、证据与数据边界

> 当前版本：2026-09-19
>
> 本文只说明数据流、层次和证据风险。工程契约与 V2 状态见 03；中期目标见 00。

## 1. 五个层次

1. 原文与版本层：四部王氏原典、外部底本和归档材料。
2. V2 机器工作层：passage、candidate、机器案例、来源状态和校验结果。
3. 中期人工复核层：AI 草稿、人工意见、修订稿和确认稿。
4. 展示层：从确认稿或明确的只读材料生成页面。
5. V2 正式 review 层：正式人工事件、状态变化和 gold gate。

当前中期重点是第 3、4 层，不是继续扩大第 2 层，也不是直接改造第 5 层。

## 2. 当前数据流

原典/旧材料
→ passage 与来源登记
→ candidate 和机器校验
→ V2 统一工作库
→ 选取中期案例
→ AI 五步草稿
→ 人工审计文件包
→ 确认版本
→ 固定成果展示

V2 正式 review 是另一条内部路径：

V2 工作库
→ target/source/evidence 解析任务
→ 受任务绑定的正式 review
→ review_events
→ human_status
→ gold 或保持未决

五步审计卡可以读取 V2 材料，但不替代外部来源核验，也不自动写入正式 review 结果。

## 3. 三类数据库

| 数据库 | 当前性质 | 中期使用 |
| --- | --- | --- |
| dictionary.db | 旧 parser 机器解析库 | 历史、兼容和迁移对照 |
| annotations.db | 旧 DOCX/AI 工作稿库 | 历史输入和案例背景 |
| annotation_v2.db | V2 统一机器工作库 | 选择案例、读取材料和建立对应 |

中期文件包不是第四个主数据库，而是少量案例的可追溯研究工作源。默认不直接写生产 V2 数据库。

## 4. 机器层和人工层

机器层负责 passage、candidate、旧材料适配、quote/offset/schema/enum 校验、来源状态和 AI 草稿。

人工层负责案例边界、问题和结论、证据作用、推理跳步、结论强度和未决事项。

机器校验通过只说明结构和来源链达到机器门槛，不表示学术结论正确。

## 5. 主要证据状态

| 状态 | 可以说明什么 | 不能说明什么 |
| --- | --- | --- |
| canonical source passage | 当前登记版本中有可定位文字 | 不自动证明解释正确 |
| secondary citation match | 王氏正文或旧材料中出现相同文字 | 不等于外部原典已核验 |
| external source pending | 需要补外部来源 | 不等于引文错误 |
| candidate available | 有候选文件或页面 | 不等于 canonical |
| legacy derived passage | 由旧机器材料派生的定位载体 | 不等于原典证据 |
| machine draft | 机器材料结构可保存 | 不等于人工确认或 gold |

full JSON 只可作为旧标注上下文和迁移线索，不能替代 canonical passage、版本和外部原典核验。

## 6. 四类风险

### 6.1 来源身份

同一 work_key 和 source_file 必须对应稳定来源身份。换行、格式变化或重新导入不能静默制造第二个当前来源。

活动来源应能回到稳定来源标识、文件路径、上游 revision、canonical_status、passage 和 quote。

### 6.2 外部引文

王氏正文提到外部典籍，不等于项目拥有该典籍的 canonical 底本。中期可以把它作为王氏论证材料或待核线索，但不能写成项目已经独立查见外部原典。

### 6.3 target_work 或 evidence 缺失

无法确认 target_work 时保留 unresolved；缺 evidence 时保留 rejected 或待补状态；不根据标题猜测，也不制造占位引文。

### 6.4 full JSON 命中

full JSON 的 paragraph 或 comment 命中，只证明旧标注包中出现过相同文字，不能单独证明外部版本、页码、原典准确性或 quote gate 通过。

## 7. 中期案例中的边界

- 平原之隰：区分王氏以注文支持校改和项目已经查见异本；
- 譕臣：区分字形、训义、上下文和押韵的作用；
- 造舟于河：明确原文、字形和结论中的待核问题；
- 已语终辞也：材料范围过粗时先缩小子段或暂缓。

每例确认稿都要列出已确认材料、王氏主张、项目重建、外部未核验项和下一步所需材料。

## 8. 不再作为当前主路径

archive/ 中的旧方案仍可追溯，但当前不再：

- 让成员从 DOCX 空白表格手写整条 V2 案例；
- 让旧 JSON 工作台作为主要入口；
- 让外部迁移表提交后才能进入五步卡；
- 为中期继续建设独立 candidate.db 或完整 main.db v2；
- 把全量机器候选扩张当作中期成果。
