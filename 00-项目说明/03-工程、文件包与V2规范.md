# 工程、文件包与 V2 规范

> 当前版本：2026-09-19
>
> 本文合并工程实现、V2 状态和中期文件包规则。它不替代人工判断，也不授权直接修改生产数据库。

## 1. 工程原则

1. 原典和旧材料只读。
2. 机器结果、人工意见、确认版本和正式 V2 状态分开。
3. 中期文件包是少量案例的唯一编辑源。
4. 页面内容只能从确认版本或明确的只读材料派生。
5. 重要结论必须能回到来源、版本和人工判断。
6. 先完成首例闭环，再考虑自动化和 V2 正式接入。

## 2. 目录边界

| 路径 | 责任 | 规则 |
| --- | --- | --- |
| 04-项目文献/A-原著原典/ | 王氏原典 Markdown | 只读 |
| 04-项目文献/D-标注/ | DOCX、旧 AI JSON、full JSON | 历史输入和对照 |
| v2/data/real_runs/ | V2 数据、报告和任务包 | 不手工编辑 |
| v2/src/、v2/scripts/ | V2 代码和校验工具 | 只做必要改动 |
| v2/research/midterm-pilot/ | 中期案例文件包 | 本阶段唯一编辑源 |
| 03-项目网站/web/ | 页面和固定展示 | 从确认内容生成 |

## 3. 中期文件包

每例至少保留：

- 稳定 case_id 和 V2 对应关系；
- source 文件、位置、版本和上下文；
- AI 初稿及材料范围；
- 原始人工意见；
- 修订稿；
- 人工确认版本；
- 未决事项；
- 展示版本或生成指针；
- 实际人工工时和 AI 辅助时间。

建议目录：

    v2/research/midterm-pilot/

      case-02-wu-chen/
      case-03-zao-zhou-yu-he/

建议每例文件：

| 文件 | 内容 |
| --- | --- |
| 00-case-manifest.md | case_id、命题、范围、版本和审校人 |
| 01-source-snapshot.md | 原文、位置、上下文和读取说明 |
| 02-ai-draft.json | AI 原始五步草稿和生成配置 |
| 03-human-review.md | 独立阅读、逐步决定、修改理由和未决项 |
| 04-revised-version.md | 修订稿 |
| 05-confirmed-version.md | 人工确认的中期正文 |

确认版本发生实质修改后，原确认状态失效，必须重新确认。页面不能另维护第二份实质正文。

## 4. V2 数据库边界

V2 可以保存经过机器校验的 machine draft，但中期 pilot 默认不直接改生产数据库。

| 类型 | 保存位置 | 能否改变案例状态 |
| --- | --- | --- |
| 五步 AI 草稿和人工逐步意见 | five_step_audit_records | 不能 |
| target/source/passage resolution | 对应 resolution events | 不能直接晋级 gold |
| 正式 case review | review_events | 只有满足 gate 才可能改变状态 |

五步审计记录开关是 V2_FIVE_STEP_AUDIT_WRITE_ENABLED；正式 V2 review 开关是 V2_REVIEW_WRITE_ENABLED。二者不得合并。

## 5. V2 状态

| 字段 | 值 | 含义 |
| --- | --- | --- |
| machine_status | pending、draft、approved、rejected | 机器运行与校验 |
| human_status | pending、approved、rejected、uncertain | 正式人工审校 |
| review_status | pending、approved、rejected、uncertain | 查询用人工镜像 |
| lifecycle | machine_draft、human_review、gold、rejected | 案例晋级阶段 |

machine_status=approved 只表示机器校验通过，不表示学术结论正确或人工确认。

五步步骤使用局部状态 pending、accepted、edited、question；审计记录使用 active、superseded、deleted。这些不能替代 human_status。

## 6. 正式 V2 review gate

正式 approved 至少需要：

1. reviewer；
2. source、target、evidence、process、conclusion 等字段决定；
3. evidence 逐条决定；
4. canonical target passage；
5. quote gate 通过；
6. 可追溯 operation_id 和 review event。

不满足时保留 machine_draft、human_review、uncertain 或 rejected，不进入 gold。

## 7. AI 五步生成契约

五步字段固定为：

problem_discovery、research_question、evidence_collection、reasoning、conclusion。

当前模型为 deepseek-flash、deepseek-v4-pro；effort 为 none、low、high、max。当前代码按 effort 使用不同输出预算，并限制来源段落、目标文本、过程和 evidence 长度。

生成结果至少记录：

- 请求模型和返回模型；
- reasoning_effort 和 output_budget_tokens；
- prompt_version；
- usage、generated_at、case_fingerprint；
- 输入案例和材料的稳定 ID。

AI 不得新增无法回到输入材料的 quote。schema、字段、quote、offset、enum 和来源状态由本地程序校验。

## 8. 页面契约

默认页面只展示做判断所需的信息：

- 案例和核心状态；
- 当前步骤摘要；
- 相关证据 snippet；
- AI 提醒；
- 认可、修改、存疑。

完整原文、全部 evidence、provenance、工程 ID、模型和预算放在展开层或细致模式。人工确认文本在选择修改或存疑前不强制出现。

页面不得把 machine draft 显示成已审校结论，也不得把五步记录显示成 gold。

## 9. 来源和 quote

每条来源文字至少保留 source_document_id、source_file、revision、passage_id、quote、字符偏移或非严格匹配状态、canonical_status 和 source_resolution。

严格命中只能证明文字出现在绑定 passage 中。外部来源未登记时不得写成 quote passed；full JSON 命中不得升级为 canonical。

## 10. API/SQL 命名

API/JSON 语义使用 machine_result 和 human_review；SQL 物理列可以使用 machine_result_json 和 human_review_json。文档和代码必须明确区分两层。

## 11. 版本、审计和工时

自动结果记录 schema_version、prompt_version、model、input_record_id、output_record_id、source_file、created_at 和 tool_version。

中期人工过程另外记录独立阅读、AI 准备、补查、修改、确认、总工时和 Agent 错误。Agent 时间不能替代人工时间。

## 12. 中期验收

每个案例至少通过：

1. 文件包清单完整；
2. source 和版本对应；
3. AI 草稿能回到输入材料；
4. 人工意见和修订稿存在；
5. 确认版本明确；
6. 展示只从确认版本生成；
7. 未决事项显式；
8. 没有被写成 gold 或全库完成。
