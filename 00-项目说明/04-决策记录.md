# 当前决策记录

## 1. 研究定位

决定：项目继续保留“高邮二王考据过程知识库建设及应用”的项目名称，但研究内核统一表述为“面向古籍考据任务的可追溯研究环境”。

理由：数据库、检索和网站是基础设施；可迁移的研究问题是如何在来源、版本、证据角色和不确定性约束下组织考据任务，并评价模型能否完成证据获取、判断和核验。

该定位是研究路线的统一解释，不追溯改写立项书、答辩材料或历史归档，也不取消原有数量承诺。

## 2. 分阶段推进

决定：当前只推进真实人工复核和文件归档；benchmark-ready corpus、generic baseline、domain-specific harness 和 agent ablation 作为后续阶段。

理由：当前 V2 仍是机器工作库，首先需要证明工程能力已经转化为可读、可追溯、可复核的研究案例。

## 3. 中期成果

决定：中期核心成果是少量“考据过程结构化复核案例”，不以机器案例数量或全库人工审校为核心。

理由：三例 pilot 可以产生真实人工判断、确认版本、方法比较和单位成本；它们不冒充 60/300 数量指标、精校、benchmark gold 或 V2 gold。

## 4. 文件包优先

决定：中期文件包是案例正文和确认版本的唯一编辑源；V2 生产数据库默认只读。

理由：文件包可以先完整保留真实人工过程，避免为了几条例案例承担完整正式 review 生命周期的维护成本。第一例稳定后才允许在隔离副本中限时试接 V2。

## 5. 五步卡的边界

决定：五步释证卡保存 AI 草稿、逐步人工决定和审计记录，但不自动改变 annotation_cases、human_status、review_events 或 gold。

理由：五步卡解决如何读、如何判断和如何记录；正式 V2 review 还需要目标典籍、外部版本、canonical passage 和完整字段 gate。两条路径必须分开。

## 6. Corpus 和 benchmark 分开

决定：人工复核案例、benchmark-ready case 和 V2 gold 使用不同名称；现有 retrieval benchmark 只称检索层 benchmark。

理由：检索层可以先验证召回和排序；端到端 benchmark 还需要明确答案、证据角色、难度、数据划分和评价协议。不能把 20 个检索样本写成完整考据 gold。

## 7. Agent 不以数量定义

决定：项目不以接入大模型、增加 agent 数量或建设通用平台作为进展指标。后续只在任务、工具、预算、轨迹和指标固定后评价 domain-specific harness。

理由：真正要检验的是，在相同模型和材料下，来源约束、问题分解、证据核验和拒答规则是否带来稳定收益。

## 8. 人工判断优先

决定：首例先独立阅读，再查看 AI 草稿；人工只负责问题概括、证据作用、推理关系、结论强度和未决事项五类语义判断。

理由：降低 Agent 先入叙述造成的锚定，也避免把人工时间耗在 passage_id、task_id 和 JSON patch 上。

## 9. 案例和停止规则

决定：案例顺序为平原之隰、譕臣、造舟于河；已，语终辞也仅为可选第四例。关键来源或字形问题约 30 分钟仍无明确路径时，缩小命题、保留待核或换例。

理由：前三例分别承担标准校准、有限比较和代表案例深化；第四例不应牺牲前三例的归档和展示质量。

## 10. 展示从确认稿派生

决定：固定成果页、卡片和比较文本只能从确认版本生成，页面不得维护第二份实质正文。

理由：防止页面润色覆盖真实人工过程，并保证展示中的关键解释可以回到确认稿和原文。

## 11. 证据状态不升格

决定：secondary citation match、full JSON 命中、legacy-derived passage、candidate passage 和公开候选来源都不能直接升级为 canonical quote 或 gold。

理由：它们可以帮助定位和排序人工任务，但不提供独立版本和原典凭据。

## 12. 数量口径暂不强行解释

决定：不自行解决申报材料中的“不少于 60 条”和答辩材料中的“不少于 300 条”冲突。

理由：当前没有“精校”和“精选”的换算定义。中期 pilot 作为独立的阶段性质量成果，另行报告，不冒充完成数量承诺。

## 13. 旧材料的处理

决定：旧 dictionary.db、annotations.db、旧 AI JSON、旧工作台和旧设计文档保留为迁移、对照和历史证据，不继续主导当前成员操作路径。

理由：历史材料具有溯源价值，但当前新功能统一以 V2 工作库和中期文件包为主。
