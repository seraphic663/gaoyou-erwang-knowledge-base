## 1. 状态标记

| 标记 | 含义 |
| --- | --- |
| `legacy` | 当前存在，但属于旧链路或旧 schema，不作为 V2 规范 |
| `partial` | 已有一部分实现，但未达到 V2 要求 |
| `planned` | 文档规划了，但当前工作区没有对应实现或产物 |
| `pending` | 需要 OCR、抽样、人工审校或外部依赖确认 |
| `ready-to-build` | 规范已足够明确，可以进入实现 |

## 4. 校验能力对照

| 校验项 | 当前情况 | 目标 V2 | 缺口 |
| --- | --- | --- | --- |
| JSON 结构 | V2 有 `annotation_case.v1` schema 和自定义 validator；真实案例均通过 | `annotation_case.v1` JSON Schema/Pydantic | 仍需覆盖更多旧格式和新 AI 输出 |
| quote 非空 | V2 真实案例逐字命中 passage | quote 必须是 passage 严格子串或有明确归一化结果 | 全四部和 OCR 差异仍需抽样核查 |
| quote 来源 | 当前依赖 DOCX 段落/批注索引 | quote 必须返回 passage_id、offset、hash | 旧主库 evidence 无 passage_id |
| hash | V2 真实案例记录 source、passage、quote hash | source、passage、quote、输入输出均可审计 | 已完成一部一案例验证，仍需批量运行 |
| 枚举 | 当前检查旧 `method_tags`、`relation_type`、`evidence_type` | 统一关系、状态、方法概念枚举 | 旧枚举和 V2 枚举不是同一套 |
| 模板标签 | V2 validator 已递归拒绝模板标签 | 正式入库前递归扫描并拒绝 | 需要覆盖新 AI input/output 层 |

| 四部 Markdown | 生成规范化副本和 hash，原始文件归档 | 不直接覆盖原文，不自动繁简转换或改异体字 |

## 6. V2 的完成判据

V2 不能仅以“文件生成”作为完成。至少需要同时满足：

1. 四部 Markdown 有统一 `work_key`、标题路径和版本 hash；
2. passage 能被稳定生成并被 quote 精确定位；
3. candidate 与旧模板 case 分离；
4. 旧 AI JSON 和新 AI input/output/import 路径最终都可回查到同一 V2 case；
5. schema、quote、enum、hash、模板标签和五步校验可运行；
6. `machine_result` 和 `human_review` 不混写；
7. 至少有一批真正人工确认的 gold cases，才能开展 benchmark；
8. 网站展示能明确区分候选、机器通过和人工审校状态。

目前已经满足“一部真实原典 + 一个真实案例的 V2 机器链路和统一工作库入库”这一阶段性条件；在四部全量、人工审校和 gold 集完成前，项目仍应称为“V2 原型/机器工作链路”，不能称为“V2 主库已完成”。
