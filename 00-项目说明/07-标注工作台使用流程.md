# 标注工作台使用流程

本文给已经 clone 项目的成员使用。目标是：对照自己的 DOCX，在本地网页里填写标注，导出 `annotation_case.v1` JSON，然后通过自己的分支提交。

## 1. 每次开始前先拉最新 main

在项目根目录运行：

```powershell
git switch main
git pull
```

为本次标注新建分支：

```powershell
git switch -c annotation/你的名字-任务名
```

如果分支已经建过，切回自己的分支后同步 main：

```powershell
git switch annotation/你的名字-任务名
git merge main
```

## 2. 启动本地网站

进入网站目录：

```powershell
cd 03-项目网站
npm install
npm start
```

浏览器打开：

```text
http://localhost:3000/annotation-workbench.html
```

如果 3000 端口被占用，先关掉旧的 `npm start` 窗口，再重新启动。

## 3. 打开自己的 DOCX

当前三份起始标注材料在：

```text
04-项目文献/D-标注/广雅疏证_徐健怡.docx
04-项目文献/D-标注/经传释词第二-㠯以已_李汶灿.docx
04-项目文献/D-标注/读书杂志_平原之隰-譕臣_卢飞宇.docx
```

做标注时同时打开 DOCX 和网页。DOCX 负责看原文、批注和上下文；网页负责把你的判断整理成统一 JSON。

## 4. 在网页里填写

推荐顺序：

1. 选择来源 DOCX。
2. 填 `案例标题`、`提交者`、`二王出处`、`被考据作品`、`被考据原文`。
3. 填一组 `字词关系`：原文对象和训释/校正对象必须有。
4. 从 DOCX 复制相关原文到“材料摘录区”。
5. 在“材料摘录区”选中一句证据，点击“选中文字加入证据”。
6. 填结论。发疑、设问、取证、释理能写就写，不确定可以留空，不要硬凑。
7. 方法画像不确定可以先不填，审校者后面会统一。

最少必须填 9 项：

1. `case_title`
2. `submitted_by`
3. `source_work`
4. `target_work`
5. `target_text`
6. `term_relations[].source_term`
7. `term_relations[].target_term`
8. `evidences[].quote`
9. `conclusion`

网页会自动保存草稿到本机浏览器。刷新页面一般不会丢，但不要把浏览器本地数据当作正式备份；做完一条就导出 JSON。

## 5. 导出 JSON

右侧“导出”区域会提示缺项、模板标签、quote 是否需要核对。基础检查通过后点击：

```text
下载 JSON
```

把文件放到：

```text
04-项目文献/D-标注/json/人工标注/你的名字/
```

如果目录不存在，可以新建。一个案例一个 JSON 文件，不要把多条案例塞进同一个文件。

## 6. 提交分支

回到项目根目录，检查状态：

```powershell
git status
```

只添加本次导出的 JSON 和必要说明，不要 `git add .`：

```powershell
git add "04-项目文献/D-标注/json/人工标注/你的名字/文件名.annotation.json"
git commit -m "annotation: add 你的案例标题"
git push -u origin annotation/你的名字-任务名
```

然后在 GitHub 上创建 Pull Request，等待审校。审校通过后，项目负责人会再导入 `annotations.db`，成员不要手工改数据库文件。

## 7. 填写注意

- quote 必须复制原文，不要意译。
- `【必填】`、`【建议】`、`【选填】` 这类模板标签不能出现在导出的正式 JSON 中。
- `evidence_role` 是单条证据的作用，`method_profile.concepts` 是整案现代方法标签，不要混填。
- `source_passage_id`、`passage_id`、`quote_sha256` 可以由程序后补；不知道就留空。
- `relation_type`、`relation_subtype` 不确定可以留空，审校时统一。
- 不要直接改 `annotations.db`、`sqlite-snapshot.json`、`annotation-snapshot.json`。

## 8. 常见问题

Q：网页是不是直接把数据交给负责人？

A：不是。第一阶段只生成本地 JSON，通过 Git 分支和 PR 提交。这样每条标注都能审查、回滚和校验。

Q：刷新页面后草稿还在吗？

A：通常还在，因为网页自动保存到浏览器 `localStorage`。但换浏览器、清理缓存或换电脑会丢，所以做完要导出 JSON。

Q：我不会判断方法标签怎么办？

A：可以留空。第一轮最重要的是案例边界、字词关系、证据 quote 和结论。

Q：一个 DOCX 里有多个案例怎么办？

A：网页里新建多个草稿，一个案例导出一个 JSON。
