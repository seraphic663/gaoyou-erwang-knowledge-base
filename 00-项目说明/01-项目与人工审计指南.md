# 项目与人工审计指南

> 当前版本：2026-09-19
>
> 本文是中期参与者的唯一操作入口：先理解项目，再按五步卡完成案例审计和文件归档。

## 1. 项目是什么

本项目研究王念孙、王引之（二王）的考据过程。重点不是单纯建立字词索引，而是让读者理解：

- 王氏在处理什么问题；
- 哪些材料承担了什么证据作用；
- 王氏如何从疑点走到解释或校改；
- 哪些是王氏主张，哪些是项目重建，哪些仍待核验。

中期成果名称统一为“考据过程结构化复核案例”。它不是机器草稿，不自动等于精校，也不自动等于 V2 gold。

## 2. 当前人工流程

1. 从 V2 工作库选择案例。
2. 固定本次复核的主要命题、原文范围和版本。
3. 先独立阅读王氏原文，写下自己的问题和主张理解。
4. 从案例详情进入五步释证卡，生成 AI 辅助草稿。
5. 逐步检查草稿、证据和来源状态。
6. 每一步选择认可、修改或存疑，并记录理由。
7. 将 AI 初稿、人工意见、修订稿、确认稿和未决事项归档。
8. 只从确认稿生成固定展示。

AI 是备料和整理工具，人工负责判断。人工不需要填写 passage_id、task_id、operation_id 或 SQL patch。

## 3. 五步判断标准

| 步骤 | 要回答的问题 |
| --- | --- |
| 问题发现 | 疑点从哪里来，为什么需要考据 |
| 研究问题 | 本案要解决的具体问题是什么 |
| 证据收集 | 使用了哪些材料，各自属于什么证据类型 |
| 推理 | 证据如何支持或限制判断 |
| 结论 | 在当前范围内可以作出什么强度的判断 |

五步允许缺项，但不允许为了完整而补造原文没有的推理。结论必须明确边界。

## 4. 五步卡怎么审

默认先看：

- 案例标题、来源和机器/人工状态；
- 当前步骤的 AI 摘要；
- 相关 evidence snippet；
- AI 提醒核查的问题。

完整原文、全部 evidence、provenance、原始 ID、模型配置和预算放在展开层。五个步骤不默认全部展开。

每一步只能作一个决定：

- 认可：当前草稿可以保留；
- 修改：人工改写并说明原因；
- 存疑：保留限制或待核事项，不强行确定。

认可时不必重复抄写 AI；修改或存疑时必须写人工文本或理由。

每条关键证据都要问：

1. 文字是否存在于当前绑定材料？
2. 它是王氏原文、王氏引用、项目整理还是外部材料？
3. 它在本案中承担什么作用？
4. AI 是否把“出现过”写成“已经核验”？
5. 结论强度是否超过证据？

## 5. 模型、工时和记录

当前五步卡允许选择：

- 模型：deepseek-flash、deepseek-v4-pro；
- effort：none、low、high、max；
- 默认建议：deepseek-flash + high。

生成和保存时记录请求模型、返回模型、effort、预算、prompt 版本、用量、案例指纹、审校人和时间。

人工还要记录独立阅读、AI 准备、补查、修改和确认时间。Agent 时间不能代替人工时间，也不能单独证明质量。

## 6. 案例完成标准

只有同时满足以下条件，才称为结构化复核完成：

1. 案例边界明确；
2. 原文文件、位置和版本明确；
3. 关键解释可以回到材料；
4. 人工判断了证据作用和推理关系；
5. 王氏主张、项目重建和项目独立核验边界分开；
6. 有人工意见、修订依据、确认版本和未决事项。

这不等于全部外部底本已核验，也不等于王氏结论已被项目重新证明。

## 7. 文件包和协作

中期文件包位于 v2/research/midterm-pilot/，详细结构见 03-工程、文件包与V2规范.md。

原典、旧数据库、旧 AI JSON 和 V2 生产数据库保持只读。成员不直接编辑 annotation_v2.db，不把 machine draft 改成 approved，不把 uncertain 写成精校。

建议一例一个目录，保留 AI 初稿、人工意见、修订稿、确认稿、展示稿、未决事项和工时记录。确认版本发生实质修改后，必须重新确认。

## 8. 协作和 Git 最小规则

- 先确认工作区和分支，不覆盖他人未提交内容；
- 只提交本次明确的案例文件包或说明文件；
- 不使用 git add . 或 git add -A；
- 不提交 API key、缓存、数据库 journal、临时 PDF 和大体量归档；
- 提交前运行 git diff --check；
- 未经明确要求，不 push、不合并、不改写远程历史。

常用命令：

    git status
    git diff --check
    git add <明确的文件路径>
    git commit -m "midterm: describe the audited case or document change"

## 9. 不应误报

- 页面能生成五步，不等于案例完成；
- 五步审计记录不等于正式 V2 review；
- secondary citation match 不等于外部原典已核验；
- machine_status=approved 不等于人工通过；
- 三例 pilot 不等于完成 60/300 数量承诺；
- Agent 辅助不等于质量等级。
