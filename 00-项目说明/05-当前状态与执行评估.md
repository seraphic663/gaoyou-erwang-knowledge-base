## 3. 是否具备开工条件

具备。已有 passage、V2 工作库、五步卡、审计记录和来源状态，不需要再以“重新设计数据库或工作台”为开工前提。

真正缺口是把工程能力转换成至少一例真实、可追溯、可展示的人工复核成果。

## 4. 首例门槛

开始平原之隰前必须确定：

1. 一个主要复核命题；
2. 王氏原文文件、位置和版本；
3. 纳入的上下文和证据；
4. 王氏主张、项目重建和项目未核验部分；
5. 明确保留的未决项；
6. 文件包和工时记录位置。

## 5. 20 小时工作包

| 工作包 | 预算 | 交付 |
| --- | ---: | --- |
| A 案例复核 | 9 小时 | 三例中的人工判断、修订和确认 |
| B 证据与版本归档 | 3 小时 | 初稿、意见、修订稿、确认稿、展示稿链 |
| C 规则与方法提炼 | 2 小时 | 一页规范、一组有限比较、Agent 帮助与错误 |
| D 固定成果展示 | 4 小时 | 一个稳定阅读入口 |
| 返工缓冲 | 2 小时 | 一致性和意外问题 |

执行顺序：

A 首例校准 → B 同步建版本链 → A 完成其余案例 → C 提炼 → D 展示。

## 6. 风险和停止条件

| 风险 | 应对 |
| --- | --- |
| AI 叙述造成锚定 | 首例先独立阅读 |
| 外部引文缺版本 | 保留未决，不写成 canonical |
| 案例范围过大 | 缩小命题，不硬填五步 |
| 页面和确认稿分叉 | 页面只从确认稿生成 |
| V2 接入拖延 | 文件包先行，隔离试接限时一小时 |
| 时间不足 | 先取消第四例，再减少核心案例 |

出现以下情况应停止扩展功能：

- 连续案例都需要大幅重写 AI；
- 人工总负担没有下降；
- 关键来源问题约 30 分钟仍无可控路径；
- 页面开发开始挤占案例复核；
- V2 接入要求改生产数据或补全全库队列。

## 7. 不在本轮范围

- 全库人工审校；
- 全部 target_work、外部来源和外部 passage 消歧；
- 全面 canonical 底本核验；
- 批量自动升 gold；
- 通用 Agent 平台；
- 无关架构重构；
- 继续扩大旧 parser 模板案例。

申报材料“不少于 60 条”和答辩材料“不少于 300 条”的口径冲突仍未解决。三例 pilot 只能作为可信的阶段性成果，不能冒充完成数量承诺。

## 8. 统一验收问题

沿任一案例倒查：

> 展示中的关键解释能否回到确认版本；确认版本能否回到真实人工意见和修改依据；修改依据能否回到确定的王氏原文；下一例能否用同一规则继续处理？
不能回答其中任一环，就不能称为结构化复核完成。
