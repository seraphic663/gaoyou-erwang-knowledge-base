# 项目与人工审计指南

> 操作边界复核于 2026-10-31。本指南描述人工判断，不替成员填写数据库字段。

## 1. 先确认工作对象

人工复核的目标是重建一条具体的二王论证路径：问题是什么、二王提出什么解释、每项材料承担什么作用、推理如何推进、结论覆盖到哪里。确认前不要把文本差异、机器关系或 AI 总结当成已定判断。

按数据来源区分两条流程：

- 标注 DOCX 转换流程见 [data/D-标注/README.md](../../data/D-标注/README.md) 和项目 skill。DOCX、转写、案例 Markdown、JSONL 与 `annotations.db` 是一条导入链。
- 结构化复核案例使用 `research/midterm-pilot/` 文件包，或在明确授权的隔离 V2 工作副本中操作。V2 状态不得由标注库导入或网站展示自动改变。

## 2. 人工复核步骤

1. 固定案例命题、原典文件、位置、版本和必要上下文。
2. 先独立阅读王氏原文，写下疑点和主要主张，再查看 AI 或机器候选。
3. 逐条确认引文文字、来源身份、版本状态和原文位置。
4. 判断证据支持、限制还是改变哪一步解释；记录王氏原文是否明确说明。
5. 检查推理有无漏步、跳步、语义扩张或模型添加的连接。
6. 写出本案结论和适用范围；无法确认的关系保留为待核或未决。
7. 保存人工意见、修订稿、确认版本和生成展示的来源指针。

## 3. 案例完成标准

案例只有在边界、原文版本、关键证据作用、推理关系、结论范围和未决事项均经人工确认后，才可称为结构化复核完成。必要时另行定义更高的底本、引文或专业判断校核要求；不能用“结构格式通过”代替这些判断。

五步草稿允许写“未显述”或“待核”，不为填满字段补造王氏没有写出的推理。AI 负责定位、整理和提示；人工负责语义判断。

## 4. 文件和状态

文件包应保存原文快照及位置、AI 初稿、人工意见、修订稿、确认稿、未决事项和工时。确认稿发生实质改动后重新确认。展示页面不得另维护一份脱离确认稿的正文。

以下状态不可互换：机器候选、草稿/待核的人工撰写案例、结构化复核案例、benchmark-ready case、V2 gold。页面能生成五步或 case 字段通过 schema 检查，都不表示案例通过学术复核。

## 5. 协作

- 每次人工复核前确认分支与工作区，不覆盖其他人的未提交工作。
- 只提交本次明确的项目路径；原始材料、人工意见和测试数据按目录规则分别处理。
- 不提交 API key、运行缓存、数据库 journal 或临时发布目录。
- push、合并或改写远端历史均须有明确指令。
