# 工程、文件包与 V2 规范

> 当前版本：2026-09-30
>
> 本文是工程和数据契约。它不替代人工学术判断，也不授权直接修改生产数据库。

## 1. 工程原则

1. 原典和旧材料只读。
2. 机器结果、人工意见、确认版本、benchmark-ready 状态和正式 V2 状态分开。
3. 中期文件包是少量案例的唯一编辑源。
4. 页面内容只能从确认版本或明确的只读材料派生。
5. 重要结论必须能回到来源、版本和人工判断。
6. 先完成首例闭环，再考虑自动化和 V2 正式接入。
7. 只有在任务、工具、预算和指标都固定后，才把流程称为 agent harness 实验。

## 2. 目录边界

| 路径 | 责任 | 规则 |
| --- | --- | --- |
| data/A-原著原典/ | 王氏原典 Markdown | 只读 |
| data/D-标注/ | DOCX、旧 AI JSON、full JSON | 历史输入和对照 |
| v2/data/real_runs/ | V2 数据、报告和任务包 | 不手工编辑 |
| v2/src/、v2/scripts/ | V2 代码和校验工具 | 只做必要改动 |
| research/midterm-pilot/ | 中期案例文件包 | 本阶段唯一编辑源 |
| solution/website/web/ | 页面和固定展示 | 从确认内容生成 |
| research/analysis/benchmarks/ | 检索或任务评价 manifest | 只保存明确版本的评价定义 |
| ops/ | Docker、Node 运行时依赖和部署构建契约 | 由根 `railway.toml` 指向，不放研究材料 |
| docs/operations/ | 一致性、迁移和 Markdown 治理 | 记录当前结构和检查规则，不替代历史档案 |

## 3. 中期文件包

每例至少保留：

- 稳定 case_id 和 V2 对应关系。
- source 文件、位置、版本和上下文。
- AI 初稿及材料范围。
- 原始人工意见。
- 修订稿。
- 人工确认版本。
- 未决事项。
- 展示版本或生成指针。
- 实际人工工时和 AI 辅助时间。

建议目录：

    research/midterm-pilot/
      case-01-pingyuan-zhi-xi/
      case-02-wu-chen/
      case-03-zao-zhou-yu-he/
      case-04-yi-yu-zhong-ci-ye/

建议每例文件：

| 文件 | 内容 |
| --- | --- |
| 00-case-manifest.md | case_id、命题、范围、版本和审校人 |
| 01-source-snapshot.md | 原文、位置、上下文和读取说明 |
| 02-ai-draft.json | AI 原始五步草稿和生成配置 |
| 03-human-review.md | 独立阅读、逐步决定、修改理由和未决项 |
| 04-revised-version.md | 修订稿 |
| 05-confirmed-version.md | 人工确认的中期正文 |
| 06-display.md | 从确认稿派生的展示文本 |
| 07-open-issues.md | 外部来源、版本、字形等未决项 |
| 08-time-log.md | 阅读、AI、补查、修改和确认工时 |

确认版本发生实质修改后，原确认状态失效，必须重新确认。页面不能另维护第二份实质正文。

## 4. 案例和 benchmark 状态

状态名称必须说明层级，不能把不同系统的状态混用：

| 状态 | 产生位置 | 允许的表述 |
| --- | --- | --- |
| machine draft | V2 机器工作库 | 机器材料已保存 |
| structure-reviewed case | 中期文件包 | 指定范围的论证重建已人工确认 |
| benchmark-ready case | benchmark manifest 或研究文件 | 已具备任务、答案、证据角色、难度和评价字段 |
| V2 gold | 正式 review gate | 已通过数据库正式审批 |

检索 benchmark v1 是 retrieval-layer 诊断工具。它可以使用稳定的 source passage 和案例关系，但不能据此宣称相关案例已经完成端到端人工审校。

未来 benchmark-ready manifest 至少应记录 task_id、case_id、task_type、question、answer schema、evidence roles、source/version、hard negatives、unresolved 规则、difficulty、split、reviewer 和 manifest version。

## 5. V2 数据库边界

V2 可以保存经过机器校验的 machine draft，但中期 pilot 默认不直接改生产数据库。

| 类型 | 保存位置 | 能否改变案例状态 |
| --- | --- | --- |
| 五步 AI 草稿和人工逐步意见 | five_step_audit_records | 不能 |
| target、source、passage resolution | 对应 resolution events | 不能直接晋级 gold |
| 正式 case review | review_events | 只有满足 gate 才可能改变状态 |

五步审计记录开关 V2_FIVE_STEP_AUDIT_WRITE_ENABLED 与正式 V2 review 开关 V2_REVIEW_WRITE_ENABLED 必须分开。打开前者不改变 annotation_cases、human_status、review_events 或 gold。

## 6. 正式 V2 review gate

正式 approved 至少需要：

1. reviewer。
2. source、target、evidence、process、conclusion 等字段决定。
3. evidence 逐条决定。
4. canonical target passage。
5. quote gate 通过。
6. 可追溯 operation_id 和 review event。

不满足时保留 machine_draft、human_review、uncertain 或 rejected，不进入 gold。

## 7. AI 五步生成契约

五步字段固定为：

    problem_discovery
    research_question
    evidence_collection
    reasoning
    conclusion

生成结果至少记录请求模型和返回模型、推理设置、输出预算、prompt version、usage、generated_at、case fingerprint 以及输入案例和材料的稳定 ID。

AI 不得新增无法回到输入材料的 quote。schema、字段、quote、offset、enum 和来源状态由本地程序校验。

五步草稿是 AI 辅助审计材料，不自动称为 agent 结果。后续 agent harness 实验还必须记录查询改写、工具调用、检索范围、状态变化、停止或拒答理由、证据核验和总预算。

## 8. 页面契约

默认页面只展示做判断所需的信息：

- 案例和核心状态。
- 当前步骤摘要。
- 相关证据 snippet。
- AI 提醒。
- 认可、修改、存疑。

完整原文、全部 evidence、provenance、工程 ID、模型和预算放在展开层或细致模式。页面不得把 machine draft 显示成已审校结论，也不得把五步记录显示成 gold。

固定成果页、卡片和比较文本只能从确认版本派生。页面若发生实质解释变化，必须回到文件包重新修订和确认。

## 9. 来源和 quote

每条来源文字至少保留 source_document_id、source_file、revision、passage_id、quote、字符偏移或非严格匹配状态、canonical_status 和 source_resolution。

严格命中只能证明文字出现在绑定 passage 中。外部来源未登记时不得写成 quote passed；full JSON 命中不得升级为 canonical；candidate passage 不得直接升级为外部原典。

## 10. 版本、审计和工时

自动结果记录 schema_version、prompt_version、model、input_record_id、output_record_id、source_file、created_at 和 tool_version。

中期人工过程另外记录独立阅读、AI 准备、补查、修改、确认、总工时和 Agent 错误。Agent 时间不能替代人工时间。

## 11. 中期验收

每个案例至少通过：

1. 文件包清单完整。
2. source 和版本对应。
3. AI 草稿能回到输入材料。
4. 人工意见和修订稿存在。
5. 确认版本明确。
6. 展示只从确认版本生成。
7. 未决事项显式。
8. 没有被写成 gold、精校或全库完成。
