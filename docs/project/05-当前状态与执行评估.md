## 讹误与通假统计

目前**没有**经过统一分类和逐条人工核验的四书讹误、脱讹、误字或通假总量。旧库的“音训·通假字”、人工案例中的自由文本标签、V2 `relation_subtype` 和新机器库的 relation types 计数单位不同，不能直接相加。当前机器库中的 1,804 条 `loan` 与3,741条校勘关系仅是机器关系主张记录；应结合去重关系、来源段和人工审核状态重新分类后，才可形成研究统计。详见本地研究材料及其各自日期。

## GitHub 与 Railway

- 截至 2026-10-31，本轮已将机器库功能、保存的项目工作和文档更新纳入 `main`；本地 `main` 与 GitHub `main` 已同步。
- Railway 的机器库 run id 和 `machine_library_sha256` 与 `runtime-bundle/machine-library.manifest.json` 相同，说明线上机器功能与仓库所记录的机器库版本一致。
- 分支评审发现：短 Markdown 段内的 claims 可能被一并聚成一个校读点；需要核对同段多个独立读法的拆分要求。机器库代码未包含本地被 Git 排除的 ParseBench 报告与回归材料。
- 本地 ParseBench 报告记录了 45/45 条定向 parser 回归和 32 种模块组合；它明确是约束性回归集，不是随机或穷尽的学术金标。报告及脚本受 `.git/info/exclude` 排除，GitHub 上没有对应文件或 CI 状态。
- 项目 README、网站运行说明和研究状态文档已同步到新路由、API、构建命令及数据边界；ParseBench 回归材料仍留在本地。

## 下一步

1. 先核对同段多校读点的案例拆分，并将足以公开的 parser 回归约束放到可重复执行的位置；私有/忽略的 ParseBench 结果继续留在本地。
2. 依据来源、关系组、计数单位和审核状态，定义机器统计与学术统计之间的规则。
3. 从人工撰写案例中建立少量真实确认记录；不得以机器评分、页面标签或草稿数量升格。
4. 抽查线上字词视图和案例视图，重点检查段落内多个独立校读点是否被合并；必要时修正 parser 并补上可公开复跑的回归材料。

## 判定边界

结构、外键、引文回切和 HTTP 回归通过只证明对应工程性质。它们不能单独证明字词关系正确、王氏确实认定该关系、外部版本已核，或校读结论成立。
