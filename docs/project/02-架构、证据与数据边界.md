# 架构、证据与数据边界

> 当前说明复核于 2026-10-31；机器和数据库数量以 [当前状态](05-当前状态与执行评估.md) 的核查日期为准。

## 1. 研究架构

项目要把二王考据中的问题、原文、引证、证据作用、推论和未决事项连成可回查路径。工程按数据职责分开保存这些材料；同一字形、同一段文字或同一标签不会自动使不同库中的记录成为同一结论。

## 2. 当前数据流

```text
四部王氏原典 Markdown
  → relation_parser.py
  → machine_library.py
  → machine-library.sqlite3.xz / /api/machine/*
  → /library 的字词视图与案例视图

标注 DOCX
  → 文档 Markdown
  → 案例 Markdown
  → annotation_case.v1 JSONL
  → data/D-标注/05-数据库/annotations.db
  → annotation-snapshot.json / /cases?source=annotation

原典与外典索引
  → /corpus 检索
  → /reading-lab v1/v2 过程展示

V2 sources/passages/candidates
  → v2/data/real_runs/annotation_v2.db
  → V2 查询与受控 human-review gate
```

## 3. 数据库和运行快照的角色

| 文件或服务 | 保存什么 | 权威边界 |
| --- | --- | --- |
| `solution/website/runtime-bundle/machine-library.sqlite3.xz` | 四书机器解析、字词、关系、校读点、证据和来源位置 | 当前网站机器库的可发布 bundle；仍属候选数据 |
| `data/D-标注/05-数据库/annotations.db` | 人工撰写来源、案例、术语、证据和过程步骤 | 人工材料库；当前案例状态仍草稿/待核，不等于正式确认 |
| `solution/website/data/annotation-snapshot.json` | 人工库导出快照 | 由人工数据库导出，不手工修改；页面展示不升格状态 |
| `v2/data/real_runs/annotation_v2.db` | V2 source、passage、candidate、case、evidence 和 review 状态 | 独立工作库；人工审核须通过 V2 gate 才改变状态 |
| `solution/website/data/sqlite-snapshot.json` / `solution/legacy-db/data/dictionary.db` | 旧 parser 字词目录及兼容快照 | 旧兼容链；不是新四书机器库，也不是人工主库 |
| Corpus/RAG 运行数据 | 原典和外典检索索引、候选材料 | 检索命中只供查找与校读参考，不自动进入案例库或 gold |

## 4. 证据和状态顺序

1. 原典版本、原文位置和字形边界决定本次核查对象；机器来源段 ID 只负责定位。
2. 二王原文说明作者提出的判断；二王引用的经传、注疏和字书是其论证材料，不自动等于本项目独立核实的版本。
3. 机器关系、文本检索命中和 AI 输出都属于候选或实验材料，必须保留来源、位置和未决状态。
4. 人工复核记录应说明每条材料承担的作用；结构格式通过不等于学术结论通过。
5. 只有明确保存的人工确认状态才能被称为确认案例；machine draft、V2 candidate、annotation snapshot、benchmark 记录和页面卡片不能互相替代。

## 5. 统计边界

讹误、脱讹、通假、训释、异文等类型需先定义关系粒度和映射规则，再分机器来源、人工来源、去重关系和审核状态统计。当前几套数据使用不同字段和计数单位，不可直接求和；未知关系保留为未知，不强制归类。

外部文献目录和数据库里的来源登记只能证明材料被记录或被检索，不能自动证明使用了正确版本。具体来源、版本和引用状态见对应报告与原始文献。
