# 数据库关系与清理状态

> 盘点日期：2026-10-31。数据库数量见 [当前状态与执行评估](05-当前状态与执行评估.md)，本文件解释身份、路径和生成关系。

## 1. 数据流

```text
四部原典
  → relation_parser.py + machine_library.py
  → solution/website/runtime-bundle/machine-library.sqlite3.xz
  → /api/machine/meta|search|detail
  → /library（同一结果的字词、案例两视图）

data/D-标注/01-原始DOCX/
  → 02-文档Markdown/ → 03-案例Markdown/
  → 04-案例JSONL/ → 05-数据库/annotations.db
  → solution/website/data/annotation-snapshot.json
  → /cases?source=annotation

四书正文 + 外典索引
  → /api/corpus/unified-search 或检索桥接
  → /corpus、/reading-lab

v2 原典/候选/旧库适配
  → v2/data/real_runs/annotation_v2.db
  → V2 查询与受控审校
```

## 2. 身份清单

| 路径 | 作用 | 是否作为当前依据 |
| --- | --- | --- |
| `solution/website/runtime-bundle/machine-library.sqlite3.xz` | 四部原典机器字词关系与案例运行包；由本地 builder 和 packer 产生 | Railway `/api/machine/*` 当前读取；候选结果，不是人工确认 |
| `data/D-标注/01-原始DOCX/` | 逐批保存原始标注 DOCX | 原始来源；只读 |
| `data/D-标注/02-文档Markdown/` | DOCX 完整转写回查 | 衍生文本；需回到原始 DOCX 核校 |
| `data/D-标注/03-案例Markdown/` | 按个案拆分的人工撰写材料 | 逐案编辑来源，保留原案例编号 |
| `data/D-标注/04-案例JSONL/` | `annotation_case.v1` 候选与转换报告 | 从案例 Markdown 生成；状态仍草稿/待核 |
| `data/D-标注/05-数据库/annotations.db` | 人工标注展示与检索数据库 | 从 JSONL/Markdown 导入；当前记录未自动升格为确认稿 |
| `solution/website/data/annotation-snapshot.json` | 网站人工库 API 快照 | 从 annotations.db 导出；不可手工改 |
| `v2/data/real_runs/annotation_v2.db` | V2 审校工作库及候选队列 | 与前两库独立；受 V2 状态与写入 gate 控制 |
| `solution/legacy-db/data/dictionary.db` 与 `solution/website/data/sqlite-snapshot.json` | 旧 parser 结果与旧页面快照 | 兼容/迁移审计；新机器构建不读取 dictionary.db |

## 3. 常见误读

- `/api/health` 的 `SQLite 实库快照` 计数来自旧 `sqlite-snapshot.json`，不是 `/api/machine/meta` 的机器库计数。
- `/api/annotation/bootstrap` 统计人工标注库，与 V2 `annotation_v2.db` 的案例状态分开。
- 机器库 `loan` / `emendation` 数量是关系候选记录数；case、relation group、claim、evidence 是不同粒度。
- 同一条证据可以支持多个关系，同一个案例点也可能关联多个关系；按案例数或关系组数相加可能重复。
- `v2/candidate_items.candidate_status=approved` 不等于 `annotation_cases.human_status=approved`。

## 4. 维护规则

- 机器 bundle 通过 `machine:build`、`machine:pack` 重建并核对 manifest；不要把生成产物 SQLite 当作手工编辑表。
- 人工库通过标注转换/导入脚本更新；改动后再运行 `sync:annotation` 生成网站快照。
- 旧 `dictionary.db` 及其快照保留作迁移与兼容审计，不作为新机器库缺失时的回退源。
- V2 生产库默认只读；不得通过网站快照或机器 parser 自动更改 human review / gold 状态。
- 快照、报告和数据文件均保留自身生成日期、源文件和计数口径；过期报告不覆盖当前代码或数据库。
