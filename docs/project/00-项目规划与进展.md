# 项目规划与进展

> 研究定位与阶段结构复核于 2026-10-31。当前数量见 [05-当前状态与执行评估](05-当前状态与执行评估.md)。

## 项目定位

高邮二王项目研究怎样把王念孙、王引之的考据论证过程显化出来，使一个判断能够从问题回到原典、引文、证据作用和推理路径。项目的核心成果是可回查、可比较的考据案例和相应的研究方法；网站和数据库承载材料组织、检索与展示。

“可复核”指的是论证路径可以被重新追寻和检查，不能缩减为新旧文本的机械对比。系统生成的字词关系、案例段落和 AI 五步回答只能帮助发现与整理候选；它们本身不能代替对二王原文的学术判断。

## 当前组成

1. **四书机器关系库**：解析《读书杂志》《广雅疏证》《经义述闻》《经传释词》，以 `/library` 展示字词关系或案例，并让两种视图共享关系、证据和来源定位。候选状态由系统保留，独立于人工标注和 V2。
2. **人工标注材料库**：沿 DOCX → 文档 Markdown → 案例 Markdown → JSONL → `annotations.db` 组织材料。它保存人工撰写的案例来源和过程记录；待核状态不因进入网站而升级。
3. **V2 工作流**：维护来源、passage、candidate、case、evidence 和正式人工审校门禁。它与网站当前机器库、人工标注灰度库分开。
4. **典籍检索与校读实验**：`/corpus` 搜索原典和外典；`/reading-lab` 比较直接校读与加入检索材料的校读。两者是研究工具，不是检索增强有效性的结论。

## 项目阶段

| --- | --- | --- |
| 资料与工程底座 | 固定四书文本、来源位置、机器候选和检索入口 | 已形成可运行原型；机器输出仍需抽查和分割校读点 |

## 下一阶段优先事项

1. 明确机器案例的切分单位，专门核对同一段落包含多个独立校读点时是否应拆分。
2. 为“讹混、脱讹、误字、通假、训释”等标签制定可追溯的映射与审核口径，再统计分来源、分状态的候选。
3. 从人工撰写材料中形成真实确认的案例，并保存原文、人工意见、修订与确认版本之间的关系。
4. 把网站、README、V2和数据库说明按当前代码与数据身份同步，保留日期化的历史实验报告。

## 不作出的推断

- 机器库 1,804 条 `loan` 关系不能称为王氏已确认的通假总数。
- 人工标注库有117条案例不等于117条正式通过审校的成果。
- V2 的 machine-draft 数量不等于人工确认量或 gold 数量。
- v1/v2 实验能够展示材料和生成过程，但目前不能单独证明 v2 的判断质量更高。
- 三例中期案例和机器库数量不能替代申报材料中不同口径的数量目标。
